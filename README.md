# ⚡ Zepto Clone — Full-Stack ML Recommendation System

> A quick-commerce grocery app with a **generated 5,060-product catalogue** (real per-item Zepto CDN images where available), a **3-layer ML recommendation engine**, Supabase Auth/RLS for identity and orders, and FastAPI as a stateless ML/utility service — built with React + FastAPI + Python.

## 🏗️ Architecture

Two backends with distinct, non-overlapping jobs — not two implementations
of the same thing. Supabase is the system of record for identity and
writes (Auth, RLS, the `place_order` RPC); FastAPI is a stateless ML/utility
service with no identity of its own — it verifies the Supabase JWT on every
request that needs to know who's calling (see `backend/app/api/auth.py`)
rather than issuing or trusting its own.

## 📊 ML Evaluation Metrics

**These numbers are computed by running the pipeline, not hardcoded.**
Run `python ml_research/02_collaborative_filtering.py` →
`03_content_embeddings.py` → `04_hybrid_ranker.py` to reproduce exactly
(all seeds are fixed for determinism).

Methodology: 1,000 synthetic users generated from 7 category-preference
personas, with 30–60 interactions per user. Models are evaluated on a
held-out 20% of each user's interactions, ranking the full remaining
5,060-product catalogue. The ranker uses an 80/20 user split and reports
user-level bootstrap 95% confidence intervals from 2,000 resamples.

| Model | Precision@10 | Recall@10 | NDCG@10 |
|-------|-------------|-----------|---------|
| Popularity baseline | 0.0025 [0.0005, 0.0050] | 0.0024 [0.0005, 0.0047] | 0.0027 [0.0006, 0.0054] |
| CF only (TruncatedSVD) | 0.0045 [0.0020, 0.0075] | 0.0054 [0.0022, 0.0092] | 0.0051 [0.0020, 0.0091] |
| CBF only (FAISS + TF-IDF) | **0.0055 [0.0025, 0.0090]** | **0.0065 [0.0032, 0.0104]** | **0.0060 [0.0027, 0.0103]** |
| Hybrid (LightGBM LambdaMART) | **0.0055 [0.0025, 0.0090]** | 0.0062 [0.0030, 0.0102] | 0.0057 [0.0024, 0.0095] |

**Honest finding:** CBF is the strongest individual signal on this sparse,
large-catalogue benchmark. The hybrid matches CBF Precision@10 and improves
NDCG@10 over popularity, but does not yet beat CBF on Recall@10 or NDCG@10.
All ML systems outperform the popularity baseline on the point estimates,
while the overlapping confidence intervals show that the differences need
larger real interaction logs before claiming statistical significance.
Feature importance identifies `cbf_score`, `price_norm`, and `popularity` as
the leading LambdaMART features.

**Caveat:** these are synthetic persona-based interactions (documented in
`02_collaborative_filtering.py`), not real user data. The catalogue is
generated and item-level interactions remain sparse, which is why absolute
@10 values are low. The pipeline architecture (CF → CBF → LambdaMART) is
the same one you'd point at real interaction logs; swap
`generate_synthetic_interactions()` for a real data loader to use it on
production data.

For statistical-significance methodology (A/B testing, sample sizing,
sequential testing / peeking problem), see
`ml_research/05_ab_testing_simulation.py` — also fully runnable, with
results reported honestly (one comparison is significant, one is not).

## 🛠️ Tech Stack

| Layer | Technology |
|-------|-----------|
| Frontend | React 18, Vite, TypeScript, Zustand, React Router |
| Auth / Identity | Supabase Auth (email+password), verified server-side via JWT — `backend/app/api/auth.py` |
| Backend | FastAPI (stateless ML/utility service — no identity of its own), SQLAlchemy async, Pydantic v2 |
| Database | Supabase Postgres, Row Level Security on user-owned tables, Redis (cache + rate limiting) |
| Order placement | Postgres `place_order` RPC (`SECURITY DEFINER`), called directly from the frontend via supabase-js — re-validates price/stock/promo server-side under row locks |
| Product Images | Real Zepto CDN (`cdn.zeptonow.com`) where available per item name, stock photo fallback for the rest of the generated 5,060-product catalogue |
| CF | `scikit-learn` TruncatedSVD (implemented & runnable) — `implicit` ALS as documented upgrade path |
| CBF | TF-IDF + exact cosine / `faiss-cpu` acceleration (implemented & runnable) — `sentence-transformers` (all-MiniLM-L6-v2) as documented upgrade path |
| Ranking | `lightgbm` LambdaMART (implemented & runnable) |
| LLM | Anthropic Claude API (Gopi Bahu assistant) — real streaming chat, rate-limited |
| Data | Synthetic persona-based interactions over the generated 5,060-product catalogue — see `02_collaborative_filtering.py`; Instacart-data loader documented as upgrade path |
| Deploy | Vercel (frontend), Render (FastAPI), Supabase (Postgres + Auth) |
| CI/CD | GitHub Actions |

## 🚀 Quick Start

### 1. Clone
```bash
git clone https://github.com/chapranishika/instantdeliverycloneapp.git
cd instantdeliverycloneapp
```

### 2. Supabase project
Create a project at [supabase.com](https://supabase.com), then apply the
schema/RLS/RPC migrations (from `backend/`, pointed at your project's direct
connection string): `alembic upgrade head`. This creates the tables, enables
RLS with owner-only policies, and installs the `place_order` function.

### 3. Frontend
```bash
cd frontend
npm install
cp .env.example .env.local
# Set VITE_API_URL=http://localhost:8000/api/v1
# Set VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY from your Supabase project
npm run dev
# → http://localhost:5173
```

### 4. Backend
```bash
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Fill in DATABASE_URL (Supabase), REDIS_URL, ANTHROPIC_API_KEY,
# SUPABASE_JWT_SECRET (Supabase dashboard → Project Settings → API)

python seed_db.py     # seeds products/departments/promo codes from
                       # data/processed/products.json — see CONSISTENCY.md
                       # (also creates tables if alembic wasn't run yet)

uvicorn app.main:app --reload --port 8000
# → http://localhost:8000/docs
```

### 5. ML Pipeline (train the models)
```bash
cd ml_research
python 01_eda.py                     # EDA + interaction matrix
python 02_collaborative_filtering.py  # Generate synthetic interactions + train TruncatedSVD (CF)
python 03_content_embeddings.py       # Build TF-IDF + FAISS index (CBF)
python 04_hybrid_ranker.py            # Train LightGBM LambdaMART, evaluate vs baselines
python 05_ab_testing_simulation.py    # A/B testing methodology demo (sample sizing, sequential tests)
```

## 🔑 Key Engineering Decisions

**Two backends, one job each, not two of the same job** — Supabase owns identity and writes (Auth, RLS, `place_order`); FastAPI owns ML/utility work and holds no identity of its own, verifying the Supabase JWT on every request that needs one. Order placement went through a redundant FastAPI `/checkout` implementation early on — it's been removed rather than kept in sync with the RPC, since two implementations of the same write path drift.

**Server-validated checkout** — `place_order` is a `SECURITY DEFINER` Postgres function, not a client-trusted total: it re-reads live prices/stock under row locks, enforces the promo code's `usage_limit` and `min_order_value` server-side, and decrements stock atomically — none of which a client-computed total could guarantee.

**Real CDN images** — Product images are loaded directly from `cdn.zeptonow.com` with `object-fit: contain` to preserve the white-background product photography style used by Zepto.

**Cold Start** — New users get global top-products until 5 interactions, then transition to personalised CF. Implemented via `cold_start.pkl` with per-category and global top-lists.

**Implicit Feedback** — Purchase counts converted to `log(1 + count)` confidence weights before factorisation (`02_collaborative_filtering.py`, TruncatedSVD). Standard industry approach for e-commerce implicit signals; the same weighting scheme carries over directly if you swap in `implicit`'s ALS.

**LambdaMART** — LightGBM's ranking objective optimises NDCG directly, unlike classifiers that optimise accuracy. This matters enormously for ranked list quality.

**A/B Testing** — Deterministic bucket assignment via MD5 hash of `user_id % 100`. Same user always gets same variant. Sequential testing with Bonferroni correction prevents false positives.

**Event Loop** — Every click, view, and add-to-cart fires to `/events`. Celery rebuilds the interaction matrix every night. This is the loop that makes recommendations improve over time.

## 🌐 Deploy

### Frontend → Vercel
```bash
cd frontend && npm run build
npx vercel --prod
# Set VITE_API_URL in Vercel dashboard
```

### Backend → Render
1. Push to GitHub → create a Render web service from the repo
2. Point `DATABASE_URL` at your Supabase project's pooler connection, add a Redis service
3. Set the rest of the env vars from `.env.example` (`ANTHROPIC_API_KEY`, `SUPABASE_JWT_SECRET`, `ALLOWED_ORIGINS`)
4. Render auto-deploys on push to `main`

### GitHub Secrets needed
```
ANTHROPIC_API_KEY     VERCEL_TOKEN
VERCEL_ORG_ID         VERCEL_PROJECT_ID
VITE_API_URL           SUPABASE_JWT_SECRET

```
